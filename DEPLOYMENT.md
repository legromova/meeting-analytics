# Облачный запуск на Vercel

Приложение поддерживает два режима: локальный Windows (SQLite, DPAPI, папочный импорт) и облачный (`MEETING_CLOUD=1`: PostgreSQL, Supabase Storage, Vercel Queues). Пользовательские данные локальной базы автоматически в облако не копируются.

## 1. Проект Vercel

Откройте https://vercel.com/lg5539-8032/meeting-analytics и вкладку **Settings → Environment Variables**. Секреты добавляются только там для **Production**. Ключи сервисов имеют тип Sensitive. Код первоначального администратора MEETING_BOOTSTRAP_TOKEN уже создан с типом Encrypted, чтобы владелец мог просмотреть его в настройках Vercel при первом входе. Не вставляйте ключи в чат, исходники, GitHub или переменные с префиксом NEXT_PUBLIC_. После изменения переменных всегда выполняйте **Deployments → последний production-деплой → ⋯ → Redeploy**.

Первый деплой выполнен через плагин загрузкой исходников. Если Vercel сообщает о необходимости GitHub Login Connection: откройте настройки своего аккаунта Vercel → Authentication / Login Connections → GitHub → Connect. Затем в проекте Settings → Git подключите `legromova/meeting-analytics`, ветку `main`. Это включит автоматические деплои последующих коммитов. Авторизация GitHub в Codex и подключение GitHub в Vercel — отдельные соединения.

## 2. База и приватные файлы Supabase

1. Создайте отдельный проект в https://supabase.com/dashboard (или подключите Supabase через Vercel Marketplace). Выберите регион рядом с функцией Vercel. Пароль базы сохраните в своём менеджере паролей.
2. Нажмите **Connect → Transaction pooler** и скопируйте PostgreSQL connection string. Сохраните адрес без пароля в Vercel как `DATABASE_URL`, а пароль — отдельной Secret-переменной `MEETING_DATABASE_PASSWORD`. Приложение передаёт пароль драйверу отдельно; кодировать специальные символы не нужно. Ранее настроенные URL со встроенным паролем тоже поддерживаются. Используйте pooler с IPv4 и `sslmode=require`.
3. В **Project Settings → API / Data API** скопируйте URL проекта вида `https://…supabase.co` в переменную `SUPABASE_URL`.
4. В **Settings → API Keys → Legacy API keys** скопируйте серверный `service_role` JWT в `SUPABASE_SERVICE_ROLE_KEY`. Он даёт административный доступ к Storage и должен оставаться только на сервере. Не используйте anon/publishable key.
5. В **Storage → New bucket** создайте бакет `meetings`, **Public bucket выключен**. В Vercel можно задать `SUPABASE_STORAGE_BUCKET=meetings`; это значение уже используется по умолчанию.
6. Установите допустимый размер объекта **200 МиБ (209715200 байт)** в глобальных настройках Storage и бакета. Если тариф ограничивает меньшим размером, используйте меньшие файлы либо подходящий тариф; приложение не снимает ограничения провайдера. Оплату тарифа пользователь выбирает самостоятельно.
7. Не добавляйте публичные SELECT/INSERT policies к бакету. Браузер получает только временную ссылку на конкретный объект после проверки сессии и CSRF.

Схема `meeting_app` создаётся приложением при запуске. Она не должна добавляться в список схем Data API Supabase. Таблицы доступны серверу через PostgreSQL; исходный текст встреч и сегменты туда не записываются. Не подключайте ту же БД к недоверенным Preview-веткам; для них нужна отдельная база и хранилище.

## 3. Очередь уже настроена

В опубликованном проекте включена встроенная очередь **Vercel Queues** (`MEETING_QUEUE_PROVIDER=vercel`). Создавать аккаунт Upstash, добавлять QSTASH_TOKEN или настраивать worker URL **не нужно**. Vercel аутентифицирует очередь автоматически через OIDC. Получатель — приватная функция `worker.py`, не имеющая публичного URL; передаётся только идентификатор встречи.

Задание фиксируется в PostgreSQL. Обработка имеет lease 420 секунд, повтор доставки после прерывания — через 10 минут, не более четырёх доставок. Обработчик запускает не более одной встречи одновременно. При обычной ошибке ключа, квоты или структуры ответа повторные платные запросы автоматически не выполняются: дальнейший запуск — кнопкой владельца. Максимальная длительность функций проекта — 300 секунд. Лимиты и использование очереди доступны в панели Vercel; документация: https://vercel.com/docs/queues/quickstart.

Для совместимости в коде сохранён прежний вариант QStash, включаемый при отсутствии MEETING_QUEUE_PROVIDER=vercel. В текущем деплое он не используется. MEETING_WORKER_SECRET уже создан и защищает только этот резервный HTTP-маршрут.

## 4. OpenAI и первый администратор

1. Создайте API-ключ OpenAI и задайте в Vercel `OPENAI_API_KEY` (Sensitive, Production). Локальный DPAPI-файл переносить не нужно.
2. При необходимости задайте `MEETING_ANALYSIS_MODEL` и `MEETING_TRANSCRIPTION_MODEL`. Значения по умолчанию: `gpt-4.1-mini` и `gpt-4o-transcribe-diarize`. Модель диаризации объявлена к отключению 26 февраля 2027 года; до смены модели проверьте поддержку реальных сегментов и `diarized_json` в документации OpenAI.
3. `MEETING_BOOTSTRAP_TOKEN` уже создан и сохранён. При первом входе владелец может просмотреть его в Vercel → Settings → Environment Variables. Не копируйте код в исходники и не отправляйте его в чат.
4. Выполните Redeploy. Откройте приложение. На странице первого запуска заполните почту, имя, пароль и поле «Код первоначальной настройки» значением `MEETING_BOOTSTRAP_TOKEN`. Не передавайте код ученикам. После создания первого администратора повторная регистрация первого аккаунта запрещена; других пользователей создаёт администратор.

`MEETING_CLOUD=1` задаётся при деплое автоматически. `OPENAI_API_KEY` нужен для обработки, но не для просмотра сохранённых данных. Остальные обязательные подключения проверяет `/api/health`: до настройки он возвращает 503 и список имён отсутствующих переменных без значений. При неверном DATABASE_URL возвращается безопасная страница настройки, без строки подключения и трассировки.

## 5. Проверка после настройки

1. `/api/health` возвращает HTTP 200 и `status: ok`.
2. Создайте аккаунт администратора, проект и тестовую встречу с коротким текстом. В облаке текст анализируется в одном HTTP-запросе и не сохраняется для последующих запросов.
3. Загрузите видео WebM/MP4 длительностью 120–300 секунд. Проценты относятся только к передаче в приватное Storage. После проверки файл получает устойчивое задание, далее распознаётся и анализируется автоматически. Для аудио сохраняются прежние ограничения (до 5 минут / 100 МиБ).
4. Убедитесь, что после обновления страницы сохранились встречи, результаты и личные задачи, а чужому пользователю они недоступны. Проверьте воспроизведение и перемотку.
5. При ошибке проверьте доступ к модели, баланс OpenAI, очередь Vercel Queues и лимиты Supabase. Пользователю не показываются исходные исключения сервисов.

Локальная папка Windows недоступна из облака. Её импорт сохранён в локальном режиме; в облаке используется веб-загрузка. Браузер получает только временные ссылки загрузки/чтения, которые могут действовать до срока истечения, и никогда не получает ключи Supabase, QStash, PostgreSQL или OpenAI.

## Резервные копии и ограничения

`backup.py` предназначен для локальной SQLite-базы. Для облака используйте резервные копии PostgreSQL Supabase и отдельное резервирование приватного бакета; настройки секретов восстанавливаются в Vercel. Удаление встречи удаляет связанные оригиналы и аудио через сервер, но не удаляет уже созданные внешние резервные копии. Незавершённые прямые загрузки остаются в префиксе `uploads/`; настройте их удаление по возрасту (например, 24 часа), не удаляя `video/` и `audio/`. Ни транскрипт, ни полные ответы распознавания не включаются в облачные резервные копии.

Облачное соединение с реальными PostgreSQL, Storage, Vercel Queues и OpenAI проверяется только после ввода владельцем соответствующих переменных. Тесты с подменой сервисов не подтверждают качество AI на реальной записи.
