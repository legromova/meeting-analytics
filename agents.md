# Правила работы с проектом

Это локальное веб-приложение для встреч и задач. Перед изменениями прочитайте `README.md` и затронутые модули.

## Структура

- `meeting_app/main.py` — FastAPI, авторизация, маршруты и проверки владельца данных.
- `meeting_app/db.py` — SQLite и миграции через `PRAGMA user_version`.
- `meeting_app/security.py` — хеширование паролей, сессии, CSRF и Windows DPAPI.
- `meeting_app/ai.py` — единственная граница обращений к OpenAI, схемы итогов и расшифровка.
- `meeting_app/static/` — русскоязычный интерфейс без сборки.
- `tests/test_flow.py` — интеграционные проверки.
- `backup.py` — резервная копия базы и аудио.

## Инварианты

1. Проверяйте `owner_id` для каждого проекта, встречи, аудиофайла и задачи в каждом новом API-обработчике. Роль администратора не даёт доступа к содержимому чужих данных.
2. Не сохраняйте полный транскрипт, исходный TXT или вставленный текст в SQLite, файлах, логах и сообщениях об ошибках. Предварительные сегменты могут находиться только в памяти до завершения обработки.
3. Не передавайте ключ OpenAI в браузер и не выводите его в лог. Он хранится в локальном файле, защищённом Windows DPAPI.
4. Не выводите имя человека из метки говорящего `A`, `B` и подобных. Таймкоды берите только из реальных сегментов.
5. Автоматически добавляйте в «Мои задачи» только явные поручения текущему пользователю. Повторная обработка не должна создавать дубли.
6. Сохраняйте оригинальное аудио для воспроизведения. Проверяйте фактический формат, длительность и размер до обработки; временно сжатый файл удаляйте после запроса.
7. При изменении схемы базы добавляйте следующую миграцию, не меняя уже применённую версию 1.

## Проверка изменений

Запускайте `python -m pytest -q` и `node --check meeting_app/static/app.js` после изменений затронутых частей. Для функций OpenAI используйте подмену клиента в тестах; реальный ключ в тестовый код не добавляйте. Для ручной проверки запускайте сервер только на `127.0.0.1` по командам из `README.md`.
