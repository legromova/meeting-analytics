# Локальный помощник по встречам и задачам

Локальное приложение для Windows: проекты, встречи, расшифровка аудио, сжатые итоги и личный трекер задач. База SQLite и оригинальные записи остаются на компьютере. При обработке текст встречи и аудио отправляются в OpenAI; текст расшифровки не сохраняется локально после анализа.

## Запуск

Нужны Windows 10/11, Python 3.11+ и интернет для установки зависимостей и обращения к OpenAI. В PowerShell из папки проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn meeting_app.main:app --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Первый аккаунт становится администратором. В настройках он создаёт других пользователей и задаёт ключ OpenAI. Каждый новый пользователь должен сменить временный пароль в профиле.

Сервер слушает только локальный адрес. Остановить его можно сочетанием Ctrl+C. При первом запуске миграция автоматически создаёт `data/meetings.sqlite3` и `data/audio/`. Последующие миграции применяются по версии базы SQLite (`PRAGMA user_version`).

## Настройки

Скопируйте параметры из [.env.example](.env.example) в переменные окружения PowerShell при необходимости:

```powershell
$env:MEETING_DATA_DIR = 'C:\MeetingsData'
$env:MEETING_TRANSCRIPTION_MODEL = 'gpt-4o-transcribe-diarize'
$env:MEETING_ANALYSIS_MODEL = 'gpt-4.1-mini'
```

Задавайте их перед запуском сервера. Файл `.env.example` не загружается автоматически. Ключ OpenAI вводится **только** в настройках администратора. Он защищается Windows DPAPI и хранится в `data/openai.key.dpapi`, привязанный к учётной записи Windows. Браузер получает лишь факт наличия ключа. Для восстановления копии на другом компьютере потребуется заново ввести ключ. HTTPS к OpenAI проверяется по доверенным сертификатам Windows. Служебный недоступный прокси `127.0.0.1:9` игнорируется; остальные настройки прокси сохраняются.

Модель `gpt-4o-transcribe-diarize` возвращает сегменты, временные метки и метки говорящих через `diarized_json`. Она [помечена OpenAI к отключению 26 февраля 2027 года](https://developers.openai.com/api/docs/guides/speech-to-text). При смене модели проверьте поддержку `diarized_json` в [справочнике API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create). Код интеграции находится в `meeting_app/ai.py`. Для аудио свыше 24 МБ перед отправкой создаётся временный MP3; оригинал остаётся для прослушивания.

## Как работать

1. Войдите и заполните отображаемое имя и варианты упоминания в профиле.
2. Создайте проект и встречу. Встречу можно добавить через MP3, M4A, WAV до пяти минут, TXT в UTF-8 или вставленный текст.
3. Для аудио нажмите «Расшифровать запись», проверьте предварительные сегменты и нажмите «Сформировать итоги». Для текста сразу нажмите «Сформировать итоги».
4. Откройте «Мои задачи» для личных поручений и изменения статуса. Остальные поручения остаются только в итогах.

Предварительный текст хранится только в памяти сервера до одного часа. Если сервер перезапущен или анализ завершился ошибкой, для аудио повторите расшифровку, для текстовой встречи вставьте исходный текст ещё раз. После успешного анализа исходный текст и полный транскрипт не доступны. Без ключа все сохранённые данные и аудио доступны, новая обработка объяснит, что ключ нужно настроить.

## Резервная копия

Остановите сервер, затем выполните:

```powershell
.\.venv\Scripts\python.exe backup.py C:\Backups
```

Скрипт создаст датированный каталог с согласованной копией SQLite, каталогом аудио и защищённым файлом ключа. Для восстановления скопируйте базу и `audio/` в каталог данных; на другой учётной записи Windows заново введите ключ в настройках.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют создание аккаунтов, разделение данных по владельцам, отсутствие исходного текста в базе, задачи, редактирование и загрузку трёх аудиоформатов. Для тестов `pytest` устанавливается отдельно: `python -m pip install pytest httpx`.

## Входящие видео и аналитика

Новые разделы: **Входящие записи** и **Аналитика встреч**. Приём каждого WebM/MP4 возвращает HTTP 202 после сохранения оригинала и задания SQLite; обработка начинается автоматически. Файлы: 120–300 секунд включительно, до 200 МиБ, обязательны видео и звук. Старые правила аудио/TXT/текста сохранены.

Для проверки и извлечения используется FFmpeg из установленного `imageio-ffmpeg` (отдельный ffprobe не нужен). При необходимости задайте абсолютный путь `MEETING_FFMPEG`. Проверяются сигнатура контейнера, наличие потоков, длительность из вывода FFmpeg и полное декодирование обоих потоков с тайм-аутом 120 секунд. Сырой диагностический вывод не сохраняется. Аудио сохраняется как WAV PCM 32 bit с исходными частотой и каналами, без дополнительного сжатия с потерями; это декодирование исходной звуковой дорожки. Видео остаётся неизменным. Для отправки больших WAV используется отдельный временный MP3 (моно 64 кбит/с), удаляемый после запроса.

Включите импорт для проекта во «Входящих записях». Путь: `MEETING_DATA_DIR/incoming/<owner_id>/<project_id>/`. Сканирование раз в 5 секунд при работающем сервере; ожидается неизменность размера и времени модификации минимум 10 секунд. Копируйте с временным расширением и затем переименовывайте. Проверяются только непосредственные файлы, ссылки и reparse point запрещены. Ошибочные записи перемещаются в `quarantine/`, успешные оригиналы — в `video/`. Дата папочного импорта означает момент обнаружения, её можно исправить. Windows-служба не устанавливается.

Один исполнитель берёт задания транзакцией SQLite. Lease продлевается каждые 5 секунд, срок 30 секунд. Просроченные задания возвращаются в очередь; после трёх прерываний нужен ручной повтор. При обычных ошибках ключа, сети или AI платных автоматических повторов нет. Кнопка «Повторить обработку» использует сохранённый оригинал. Хеш SHA-256 предотвращает дубли в одном проекте владельца. Старые встречи автоматически в очередь не попадают. Предыдущие итоги при ошибке повтора сохраняются; существующие личные задачи сохраняют пользовательские правки и статусы.

Сегменты речи остаются только в памяти. После аварии речь распознаётся заново. На старте удаляются оставшиеся производные из `work/`, не принадлежащие живому заданию. Резервную копию выполняйте при остановленном сервере: она содержит базу (включая очередь и настройки), `audio/`, `video/`, `incoming/`, `staging/` и DPAPI-ключ; не содержит `work/` и карантин. После восстановления запустите приложение и дождитесь истечения lease прерванного задания.

### Контракты API

Все маршруты требуют сессию владельца; изменения дополнительно требуют X-CSRF-Token. Администратор имеет доступ только к собственным встречам.

- `POST /api/incoming`: multipart `project_id`, `meeting_at` (ISO), необязательный `title`, `file`; ответ 202 `{id}`, включая найденный дубликат без повторного запуска.
- `GET /api/incoming`: `{items, errors}` только текущего владельца.
- `GET /api/analytics`: фильтры `project_id`, `start`, `end` (даты включительно), `page` от 1; `{counts:{ready,processing,errors},items,active,page,pages}`, 20 готовых встреч на страницу.
- `GET /api/meetings/{id}`: существующая встреча, итоги и безопасные метаданные (без служебных имён медиа).
- `PATCH /api/meetings/{id}`: JSON `{title,meeting_at}`; во время processing ответ 409.
- `GET /api/meetings/{id}/video`: оригинал, Range/перемотка; `?download=true` для скачивания. Аудио доступно по существующему защищённому маршруту.
- `POST /api/meetings/{id}/retry`: повтор error; при активной/успешной записи 409.
- `GET/PUT /api/projects/{id}/incoming`: `{enabled,path}` / JSON `{enabled}`. Произвольные пути не принимаются.

Облачное время обработки не фиксировано. Проверенная документация: [Speech-to-Text](https://developers.openai.com/api/docs/guides/speech-to-text), [Create transcription](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create): `diarized_json`, `chunking_strategy=auto`, лимит 25 МБ. Модель диаризации доступна существующим интеграциям до 26 февраля 2027 года; модели задаются переменными окружения из основного раздела README.

## Публикация в Vercel

Сохраняется локальный режим Windows. Для облачного режима с PostgreSQL, приватным хранилищем и встроенной очередью Vercel Queues следуйте [DEPLOYMENT.md](DEPLOYMENT.md). Переменные `OPENAI_API_KEY` и подключения задаются только в настройках Vercel; локальные данные и DPAPI-файл в деплой не включаются.
